快速上手：7 步跑通一个项目

引号中的文字与工作台上的按钮或栏目名称一致。“项目”是工作台里的基本单位，一个项目对应一个研究队列。

  1. 注册在注册页用自己的邮箱注册并完成邮箱验证，登录后进入工作台。每位成员使用自己的账号，不共用密码。
  2. 建项目在“项目 → 新建项目”填写项目名称、中心代码并选择病种模块，点创建项目。负责人可在“项目设置（仅项目负责人）”里按研究方案修改随访间隔（默认 90 天）。
  3. 录第一例在“新增患者（建立基线）”填写研究编号、性别、出生年份和已有的基线指标，点核对并保存基线。只填研究编号，不填姓名、电话、身份证号或病案号；基线血肌酐（Scr）按 μmol/L，尿蛋白/肌酐比值（UPCR）按化验单选择单位。
  4. 生成随访链接在“随访看板”该患者一行点随访链接，再点生成新链接，立即复制并只发给该患者或授权填写人。链接只在生成时显示一次，之后无法再次查看；不再需要或发错时在同一窗口撤销。
  5. 录随访患者打开链接核对后提交；患者不方便时，研究人员在“随访看板”该患者一行点录入随访直接录入。收缩压一栏可直接输入“130/80”；连续录多位患者可点“保存并录下一位”。
  6. 看数据质控问题在“数据质控问题”点查看未解决的问题，逐条点核对原记录，对照原始报告更正并填写原因。确认原值无误、无法更正时才选“接受不修复”，它不会修改原值。
  7. 导出在“导出与快照”点创建冻结版本并导出分析包，核对将冻结的项目和数据范围后确认：系统新增一个冻结数据版本（不能修改或删除），并下载基于它的分析包（数据、校验值和分析脚本）。已有版本在“数据快照”列表点“下载分析包”重新下载，不会新增版本。需要负责人或分析协作人权限；导出的分析脚本在自己电脑上运行，见进阶。
本次新增：工作台可以直接“录入随访”，不必先发链接；“随访看板”按项目的随访间隔标出逾期、14 天内到期和尚无随访的患者，逾期者排在最前；每位患者可在“研究状态”中记录知情同意与随访状态；随访链接可在患者一行集中查看和撤销。

使用前先确认三件事

  1. 研究授权：由课题负责人和所在机构确认研究方案、伦理审批（或适用的豁免）、知情同意、参与人员与数据用途。注册账号或试用不代表研究已获批准。
  2. 数据范围：只登记获批准的研究编号和字段。姓名、电话、身份证号、病案号以及“研究编号—姓名”对照表留在医院按规定保管。用研究编号替代姓名属于去标识化，不等于匿名化，记录仍按敏感个人信息管理，详见研究授权、同意与隐私。
  3. 数据存放位置与试用规则：网页、账户认证与登记数据库目前均部署在中国境内（阿里云上海），具体以隐私政策中的说明为准；机构如有院内部署等额外要求，请在录入真实数据前与我们确认。试用规则：30 天免费试用 · 含 1 个项目 · 注册无需付款信息 · 到期后转为只读，已录数据可继续查看和导出。

成员与角色

项目创建者是负责人。同事先用自己的邮箱注册并完成验证；负责人在“项目信息与协作成员”中填写同事的注册邮箱、选择角色，点添加成员。系统不会自动发送邀请邮件，请另行告知对方登录。分中心成员按同样方式加入，只能看到被授权的项目。

  • 负责人：管理项目设置与成员，录入与更正，发放和撤销随访链接，冻结与导出。
  • 录入协作人：录入、导入、更正，发放和撤销随访链接；不能导出，不能管理成员。适合研究护士 / CRC。
  • 分析协作人：查看、冻结和导出数据；不能修改记录。
  • 只读协作人：只能查看。能看到的数据仍可能被抄录，请只授权必要的人。

完整权限表、成员离组与到期后的权限见详细手册 · 成员权限。

日常随访与核对

  • 每次门诊或电话随访前看“随访看板”：“逾期”“即将到期”“尚无随访”的患者排在前面；“下次应随访”日期 = 最近一次随访（没有随访时用基线日期）+ 项目随访间隔。随访间隔由负责人按研究方案设定。
  • 两种录入方式任选：患者用随访链接自己填写，或研究人员在看板一行点“录入随访”代填。同一患者同一天内容完全相同的记录不会重复保存。录错时在该行点“随访记录”，选择“核对 / 更正”并填写原因，修改会留痕。
  • 及时填写“研究状态”：新患者的知情同意状态默认是“未确认”。请按实际情况改为“已同意”“伦理批准豁免”“拒绝”或“撤回”，并填写日期和知情同意书版本。分析脚本默认只纳入“已同意”或“伦理批准豁免”的患者。改为“拒绝”“撤回”或随访状态改为“退出研究”“死亡”时，该患者尚有效的随访链接会被系统自动撤销。
  • 单位：血肌酐（Scr）可按 μmol/L 或 mg/dL 填写，系统换算后保存为 μmol/L；UPCR 按化验单选择 mg/g 或 g/g。单位不明时先查原始报告，不按数值大小猜。缺失就留空，不用 0 代替。
  • 数据质控问题：系统按规则自动检查日期冲突、超出范围、单位可疑等，每处生成一条“数据质控问题”。更正后会自动关闭。

逐步操作见日常录入流程、随访链接、字段与单位和数据质控问题与更正；批量导入见CSV 批量导入。

冻结导出与分析

“创建冻结版本并导出分析包”会先显示项目和将冻结的数据范围，确认后把当前项目在同一时刻的数据保存为一个新的冻结数据版本，并下载 ZIP：内含十张数据表、各文件校验值（SHA-256）、Excel 查看用的副本和可在自己电脑运行的分析脚本。冻结不会阻止之后的合法更正；需要同一版本时，在“数据快照（冻结的数据版本）”列表中对该版本点“下载分析包”或“下载冻结数据（JSON）”，不会新增版本。

  • 不运行脚本也能用：CSV 为 UTF-8 编码，可直接导入 Excel、SPSS、R 或 Stata；研究编号请按文本读入，避免 0001 变成 1。
  • 运行脚本得到什么：描述性基线表（Table 1）、估算肾小球滤过率（eGFR）与 UPCR 的描述性趋势、年度随访选取、数据质控清单，以及本次实际执行步骤的英文说明（Methods 草稿，需研究团队审阅）。
  • 终点判定需要研究方案：没有经课题负责人确认的研究方案文件时，脚本只列出“未确认候选”，不是终点，也不是缓解；课题负责人在随包提供的方案模板中填写并确认终点定义后，脚本按方案判定并在运行日志中记录方案全文与校验值。临床阈值由研究方案决定，系统不预设。

运行方法和全部输出文件见下方进阶与详细手册 · 冻结与分析。

病种模块

创建项目时选择的模块决定显示哪些专病字段。模块名称不是诊断、入组资格或统计模型已验证的证明；先确认数据字典、随访时间和允许缺失的字段，再开始采集。

儿童患者（1–17 岁）：随访时填写身高，系统按床旁 Schwartz 2009 公式（0.413 × 身高 cm ÷ 血肌酐 mg/dL）估算 eGFR 并标记公式版本；未填身高则该次随访不计算 eGFR。成人按 CKD-EPI 2021，身高可不填。终点事件除肾脏结局外还可登记严重感染和住院，都要在事件细节中写明内容；疫苗接种在用药记录中登记（药物类别选“疫苗”）。每次肾活检可在“肾活检记录”中登记（自体肾或移植肾，可多次），确诊那一次标为基准活检，供按活检日对齐导出使用。研究方案需要的其他入组信息（如民族、合并症、眼底检查）由项目负责人在“自定义入组字段”中添加，在看板每位患者的“入组字段”里录入。

  • IgAN（IgA 肾病）：基线可录入牛津病理分类评分（MEST-C）。
  • LN（狼疮性肾炎）：基线可录入 ISN/RPS 病理分型、活动性与慢性指数；补体 C3/C4、抗 dsDNA 抗体按化验记录录入。
  • MN（膜性肾病）：抗 PLA2R 抗体等按化验记录录入。
  • C3G（C3 肾小球病）：基线可录入免疫荧光 C3 优势沉积、电镜分型（C3GN / DDD）、新月体比例和单克隆免疫球蛋白筛查；sC5b-9、CH50、AH50、C3 肾炎因子、H/I/B 因子与抗 H 因子抗体在化验目录的 C3G 组中，补体 C3/C4 在 LN 组中。
  • KTx（肾移植术后）：通用基线与随访字段；移植专用扩展表随导出提供，工作台暂无录入界面。

GENERAL：通用或混合病种

适合尚无专病模块的登记，如局灶节段性肾小球硬化、ANCA 相关血管炎、糖尿病肾病或混合队列。可记录通用基线、随访、化验、用药与事件；专病评分和结局口径需按研究方案另行制定。

随机分组字段

分组、随机编号和随机日期只用于登记已按获批方案产生的分配结果。系统不生成随机序列，不实施分配隐藏，也不能替代临床试验管理系统。

进阶：本地分析、研究方案、多中心合并与标准字段

以下内容面向统计人员、数据协调人员和技术负责人；日常录入用不到。

在自己电脑上运行分析脚本

  1. 保留原始 ZIP 不改动，解压后先读包内 README.md 与 analysis/README.md。
  2. 安装 Python 3.11 或 3.12，在包根目录（包含 analysis/ 的目录）建立独立环境并安装锁定版本的依赖，然后运行 python analysis/run_analysis.py。完整命令见详细手册 · 本地运行。
  3. 只有看到 DESCRIPTIVE_REVIEW_OK，新生成的 analysis/outputs/run-时间/ 才是本次结果；先看 RUN_LOG.json（人数、输入校验值、知情同意筛选人数）和 qc_issues.csv。
  4. analysis/data/ 是给脚本读的原值 CSV；用 Excel 查看请打开 excel_safe/ 中的副本，不要用它替换分析输入。

按研究方案判定终点

分析包附带 analysis/protocol_template.json。模板中的缓解定义和 eGFR 下降阈值只是示例，全部标为“需课题负责人确认”。课题负责人复制模板，逐项核对基线取值、阈值、持续确认次数与间隔、截尾规则，填写确认人和日期后，运行 python analysis/run_analysis.py --protocol analysis/my_protocol.json。脚本输出 endpoints_per_protocol.csv 与 timepoints_per_protocol.csv，并把方案全文和 SHA-256 写入 RUN_LOG.json。未确认的章节不计算。这是按方案参数的程序化判定，不等于终点委员会的人工裁定。

多中心合并

各中心在自己的项目中冻结导出，由数据协调中心（DCC）收齐各中心的六张核心 CSV，运行包内 merge_centers.py 校验合并；出现 MERGE_OK 后再对合并目录运行分析。合并保留各中心原始项目、中心代码与研究编号，冲突会阻止合并而不是自动覆盖。步骤见详细手册 · 多中心合并。

标准字段与原始来源

化验记录可保留检验项目代码（如 LOINC）、原始数值与单位；基因记录保留报告中的基因、HGVS 命名、转录本与合子状态。字段齐全不等于结果已获专业解释，不要为填满字段编造代码；分析脚本不做遗传变异解释。基因数据涉及人类遗传资源管理，工作台默认不开放录入。详见详细手册 · 专业字段。

用于注册类临床试验？

本系统用于研究随访登记，未按药物注册试验的电子数据采集要求（如 GCP、21 CFR Part 11 电子记录与电子签名、CDISC SDTM/ADaM 标准输出）进行验证。用于此类试验前需单独评估，私有化部署本身也不等于满足这些要求。
