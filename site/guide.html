1. 使用前先确认三件事

  1. 研究授权：由项目负责人和所在机构确认方案、伦理审批或相应适用路径、知情同意或豁免、参与人员与数据用途。注册账号或试用成功不代表研究已获准。
  2. 数据范围：只登记获准的研究编号及字段，姓名、电话、身份证、病案号和编号映射表留在机构批准的管理环境。编码后的健康数据仍按敏感个人信息管理；去标识化不等于匿名化。查看说明。
  3. 项目状态：登录后查看当前项目角色、可录入/可导出状态和到期提示。写入资格以项目负责人账户权益为准；到期或被锁定时应联系负责人处理，不能靠换账号继续写入。

网站前端在阿里云不等于数据库、认证、日志与备份均在境内。真实研究开始前，由机构与技术负责人核对实际服务位置及数据流；本说明不替代部署验收。见部署方式和隐私政策。

2. 负责人先添加同行，再按角色操作

每位同行使用自己的邮箱账号并完成邮箱验证。负责人选择项目，在成员区按邮箱添加 editor（录入协作人）、analyst（分析协作人）或 viewer（只读协作人）。项目创建者为 owner（负责人）。

  • 负责人：管理项目与成员、录入和核对数据、发放随访链接、冻结及导出。
  • 录入协作人：录入、导入、纠错、管理随访链接；没有专用导出或成员管理权限。
  • 分析协作人：读取、冻结和导出数据；不能修改临床记录。
  • 只读协作人：查看获授权项目的记录与质控；没有写入和专用导出权限。可阅读的数据仍可能被复制。

原 editor 被移除或降为分析/只读角色时，确认操作将撤销该项目所有有效随访链接；继续随访需重新发放。完整矩阵及到期后的行为见权限表。一个项目对应一个中心代码；不同中心独立项目需要分别授权，不会因加入一个项目而自动看到所有中心。

3. 录入、核对、纠错

  1. 选择正确项目：先核对页首项目名称、中心代码及角色，再进入“患者与基线”。已有患者用研究编号搜索，不重复建基线。
  2. 建立基线：研究编号按原样保存，例如 0001 不改成 1。填写真实基线日期、性别、出生年及已采集指标；缺失留空，不用0代替。基线日期虽可暂缺，但年度窗口和基线变化分析将不可评估。
  3. 明确单位：基线肌酐按 μmol/L 填写；基线 UPCR 选择报告上的 mg/g 或 g/g，并核对换算提示。历史无单位记录先回溯来源，不能按数值大小猜测。
  4. 完成一次随访：在“随访链接”选择患者，生成链接，仅交给授权填写人。填写人核对研究编号、日期、血压及报告单位后点“核对并提交随访”，确认成功回执。默认链接提交一次失效；详见链接管理。
  5. 处理问题：在“待办与质控”点“核对原记录”，对照来源更正并填写原因。更正后刷新复核；“接受不修复”只记录处理决定，不会修好原值，也不会让缺失或未知单位变成可分析数据。

批量录入先下载模板、核对单位和预览变更，再确认导入。当前支持基线与随访 CSV，每批最多500行且文件不超过2MB；详见导入步骤与重试。

4. 冻结数据，再运行分析包

  1. 负责人或分析协作人进入“导出”，核对当前项目并点击“冻结并导出完整分析包”或“导出分析脚本包（ZIP）”。两个入口均使用一次数据库一致性读取的冻结版本。
  2. 保留原 ZIP。research_data.json 包含项目及9张表；export_manifest.json 记录源内容 SHA-256 和包内文件校验值。版本列表可再次下载相同冻结 JSON，旧“元数据记录”不能恢复历史内容。
  3. 先读包内 README.md 与 analysis/README.md。analysis/data/ 是保留原文的机器 CSV；Excel 查看用 excel_safe/。不要用 Excel 的安全文本副本替换分析输入。
  4. 按手册配置 Python 3.11/3.12，运行脚本。看到 DESCRIPTIVE_REVIEW_OK 后检查新的运行目录、人数、qc_issues.csv、RUN_LOG.json 和 METHODS_ACTUAL_EN.md。命令与输出说明。
分析结果的边界：当前脚本处理6张核心表，生成描述统计、年度窗口记录、数值阈值候选及个人趋势；其余专病表保留但未自动分析。缺失单位、未知性别或不适用年龄不靠猜测补齐。KFRE、LME、置信区间、生存/因果分析及自动持续性临床终点判定均未执行，详见每次运行的 MODEL_STATUS.json。研究问题、终点和统计方案仍由团队确定。

冻结保留的是当时数据内容，不会阻止后续合法更正，也不等同于备份恢复、伦理审核或结果有效性证明。单独下载的各张 CSV 可能来自不同时间；需要一致的数据版本时使用冻结分析包。

5. 按研究方案选择模块

现有模块包括 IgAN、LN、MN、GENERAL 和 KTX，用于组织对应字段。模块名称不是诊断结论、入组资格或某统计模型已验证的证明。先确认数据字典、随访时间和允许缺失，再安排采集。

GENERAL：通用或混合病种

适合尚未映射到专病模块的登记。可以记录通用基线、随访、化验、用药与事件；专病评分、风险模型和结局口径需另行制定，不因选择 GENERAL 自动获得。

随机分组字段

分组、随机编号和随机日期用于登记已经按获批方案产生的分配结果。本系统这些字段不会自动生成合格随机序列、实施分配隐藏或替代试验管理。没有方案和授权时，不通过自行填写字段启动干预研究。

标准字段与原始来源

保留检验项目代码、原单位、基因报告的 HGVS/转录本及病理字段，有助于团队对照数据字典。编码完整不等于结果已获专业解释；不要为填满字段编造代码。详见专业字段说明。

6. 遇到问题，先保留现场

没有项目或按钮灰色怎么办？

核对登录邮箱、选中项目和角色提示。受邀者先完成邮箱验证，请负责人确认已添加到正确项目；到期或锁定联系负责人。不要重复创建相同队列。

提交超时，是否再填一遍？

先按页面提示重试同一次提交或重新验证链接，检查成功回执及历史记录；不要立刻新建另一条相同随访。历史读取失败不代表此前提交失败。仍不确定时请负责人核对记录。

为什么没有年度结果、eGFR 或风险值？

查看 QC 和状态文件。缺失基线日期、没有270–450天内访视、成人公式资料不足或单位待核实，都可能使对应结果不可评估；KFRE风险数值当前停用。不能用0、默认男性或猜测单位填补。

导出失败或校验不一致怎么办？

停止使用该包，保留错误文本及时间，刷新项目权限后重试。数据超过冻结容量时联系技术团队安排完整导出，不拆成不明时点的文件后声称是同一版本。不要绕过哈希检查。

需要协助时提供页面、操作步骤、错误文本和时间，先遮盖研究数据、完整随访链接及账号凭据。联系 china@kidneysphere.com；更多情形见详细错误恢复。
