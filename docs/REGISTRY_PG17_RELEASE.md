# PostgreSQL 17 发布兼容性修复

本版本 `registry-20260914-integrated-pg17-v3` 解决旧发布校验使用 PostgreSQL 18 目录、不能正确核验 PostgreSQL 17 的问题。它没有要求升级生产数据库，也不自动执行任何数据库迁移。

58 个前端文件、配置保护、原有 38 份迁移的源文件字节保持原审查版本；新增第 39 份 0037 字段对照视图权限修复。迁移顺序仍由完整文件名确定，0032–0037 为本次增量功能及权限修复。历史 `releases/registry-integrated-20260914/` 证据保持原样；旧 v1/v2 包和报告不能混用于 v3。

0037 将字段对照视图改为按当前访问者权限读取，保留字典查询，撤销普通访问者的视图写入权限。发布检查新增视图定义、所有者、选项、列和授权；若该设置退回管理员权限读取，发布会停止。

## 校验变化

- 核验协议、PostgreSQL 大版本 17、目录查询哈希、迁移清单哈希以及发布版本必须一致。
- 原有函数、触发器、策略、表授权与约束继续严格比对；新增字段类型/非空/默认值/列级权限、索引、schema 权限和付款凭证桶配置。
- 字段按名称比较，不以物理排列顺序判断兼容性；不会为改变列顺序重建表。索引仍检查键列顺序和 INCLUDE 列。
- 查询统一 UTC 和固定 search_path，避免时间默认参数因会话时区而出现不同文本。
- 保留完整的两个审查参考：全部迁移使用 LF；历史 33 份 SQL 采用 CRLF、随后六份新迁移采用 LF。必须完整匹配其中一个，不能逐函数混用或忽略源码差异。
- 参考由提交到仓库的迁移在隔离 PostgreSQL 17 环境重建，不从用户上传的生产报告生成，也不接受生产报告作为新的可信基线。

四个旧 `patient_list_*` 读取函数会由 0032 的令牌校验实现替换。输入输出签名兼容不代表还原了未知的线上定制；应在隔离项目验收实际随访读取流程。

## 本地重跑

```bash
npm ci --ignore-scripts
npm test
python3 scripts/build_registry_integrated.py /tmp/registry-pg17-v2.pyz
```

`scripts/build_database_contract_pg17.mjs --check` 重新执行两个参考路径并逐字核对提交的契约。`--write` 仅供开发阶段生成待审查参考；发布构建器不会调用它，不会自动接受变化。参考修改后必须重新审查独立 manifest 和工具哈希。

PG17 参考测试在 Linux x64 使用锁定的 `@embedded-postgres/linux-x64@17.6.0-beta.15`，运行原生 PostgreSQL 17.6 和 pgcrypto。测试库仅监听临时私有 Unix socket，不开放 TCP 端口，完成后销毁。Auth/Storage 结构及业务数据是合成的，仍不能代替托管服务集成、并发或恢复演练。旧 PG18 PGlite 回归保留为额外检查。

## 上线步骤与边界

### 隔离备份恢复演练

`npm run test:restore` 使用原生 PostgreSQL 17.6，实际运行 `pg_dump` 生成 custom 格式归档，停止并删除原测试集群，再以 `pg_restore --single-transaction` 恢复到全新的空白测试集群。目标仅限测试器创建的私有 Unix socket，不接受外部数据库地址、凭证或生产备份作为参数。

演练比较全部导出表的数据、序列状态、函数、索引、策略、表权限、schema 权限及默认权限，再执行 0032–0037 并核对 15 张有合成记录的表以及完整 PG17 契约。所需 PostgreSQL 17 客户端由 GitHub 的临时测试环境提供；安装来源为 [PostgreSQL 官方 Ubuntu 仓库](https://www.postgresql.org/download/linux/ubuntu/)。这一步不在阿里云生产服务器安装软件。

这证明审核代码在合成数据库中的导出、恢复与升级路径，不证明现有生产备份可恢复。`auth.users` 和 Storage 结构均为合成；Storage 测试仅覆盖元数据，实际文件仍须单独备份和验证。正式运行环境的登录会话、邮件、对象上传下载以及真实备份恢复仍需隔离验收。

### 正式环境验收

1. 确认登记系统专用数据库、现有 schema 和可恢复备份。不要在其他业务数据库执行登记迁移。
2. 在隔离的同版本项目中验证增量升级与恢复，再安排生产变更窗口。已有数据库不要重跑全部历史安装 SQL。
3. 数据库升级后，用 v3 精确的只读 preflight 和 `capture_registry_database.py` 生成报告。连接身份必须由正确数据库主机/用户名及完整 TLS 校验确认；SQL Editor 复制的结果可用于诊断，但不能代替这个发布身份门禁。
4. 前端发布继续要求 24 小时内报告、固定目标目录、已知 config 哈希、部署前文件捕获与邻站哨兵检查。回退仅恢复本次前端文件，不回退数据库。
5. 检查登录、成员权限、患者链接、录入、导出、付款凭证及其他四个网站。公开页面可访问不等于数据库升级验收通过。

本分支提供代码审查及离线测试，没有执行生产数据库、阿里云或 Storage 变更。生产结构清单未提交到公开仓库。
